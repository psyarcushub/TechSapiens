# Как добавить свою функцию

Продукт собирают участники конференции вместе с ИИ-агентом Гермесом. Кроме промптов в боте можно прислать код: pull request с одной своей функцией. Система сама проверит его, вольёт и выложит, а в pull request напишет, в какую версию он вошёл.

## Шаги

1. Сделайте форк репозитория и склонируйте его.
2. Создайте папку `src/features/<ваш-логин-на-github>-<короткое-название>/`, например `src/features/annasmirnova-meme-of-the-day/`. Имя только из строчных латинских букв, цифр и дефиса (логин тоже строчными), от 2 до 61 знака.
3. Положите в неё `index.tsx` с манифестом и компонентом. Образец и все правила в [AGENTS.md](AGENTS.md): что такое страница и виджет, какие есть компоненты и классы, чего делать нельзя.
4. Проверьте у себя:

   ```bash
   npm install
   npm run check
   ```

   `npm run check` проверяет типы, собирает сайт и открывает каждую страницу в браузере. Для последнего шага нужен Chrome или Chromium: обычно он находится сам, а если нет, укажите путь в переменной `CHROMIUM_PATH` или установите браузер командой `npx playwright-core install chromium`. Итог появится в `smoke-report.json`, снимки страниц в папке `smoke/`.
5. Откройте pull request в основную ветку. Описание напишите по-русски: что делает функция и зачем она стартапу.

## Что примут

- Изменения только внутри вашей одной папки в `src/features/`. Встроенную главную `home` менять нельзя.
- Файлы `.tsx`, `.ts`, `.css`, `.json`, `.svg`, `.png`, `.jpg`, `.jpeg`, `.webp`, `.md`, не больше 40 штук.
- Без новых зависимостей и без правок `package.json`, конфигов и `index.html`.
- Без запросов в интернет, внешних адресов, `iframe`, `<script>`, `eval`, `new Function` и `document.cookie`.
- Тексты интерфейса по-русски, вёрстка сначала для телефона.

Если pull request нарушает правила, Гермес не отклонит его молча: соберёт ваш замысел по-своему или объяснит, что не так.

## Лицензия

Присылая pull request, вы соглашаетесь, что ваш вклад распространяется по лицензии MIT, как и весь проект (см. [LICENSE](LICENSE)).
